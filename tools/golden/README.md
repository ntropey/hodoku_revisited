# Golden data

`Golden.java` runs the **original HoDoKu 2.2.0** solver and writes puzzles and solver
results as JSON lines. The TypeScript port is tested against that output
(`packages/core/test/golden.test.ts`), which is how we know the port finds the same
steps in the same order.

The fixtures in `packages/core/test/fixtures/` were produced like this:

```sh
# 1. fetch the original source (from SourceForge's web file browser)
python3 scripts/fetch-reference.py HoDoKu/tags/release2.2.0 ref/
# 2. compile it (--release 8: some Swing classes do not compile on newer defaults)
find ref/HoDoKu/tags/release2.2.0/src -name '*.java' > sources.txt
javac --release 8 -encoding UTF-8 -d out @sources.txt
(cd ref/HoDoKu/tags/release2.2.0/src && find . -type f ! -name '*.java' ! -name '*.form' -exec cp --parents {} ../../../../../out/ \;)
cp ref/HoDoKu/tags/release2.2.0/templates.dat out/
javac --release 8 -cp out -d out tools/golden/Golden.java
# 3. generate puzzles with HoDoKu's own generator, then solve them
java -Djava.awt.headless=true -cp out Golden gen 200 | grep -E '^[0-9.]{81}$' > puzzles.txt
java -Djava.awt.headless=true -cp out Golden solve < puzzles.txt | grep '^{' > golden.jsonl
```

HoDoKu writes a `hodoku.hcfg` options file to its working directory on first start; run it
from a scratch directory.

The puzzles were generated by HoDoKu's generator, so there are no rights issues with them.
